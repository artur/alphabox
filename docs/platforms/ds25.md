# AlphaServer DS25 work packet

The second Titan board ([titan.md](titan.md)), after the ES45
([es45.md](es45.md)).

**Branch**: `platform/titan-es45` · **Config**: `platform = "ds25";`
· **Status**: L1 (its update utility's console runs to "starting drivers"
and then faults); not further

## The machine

| | |
| --- | --- |
| Family, code name | Titan; Linux calls it "Granite" (sys_titan.c), with the generic Titan vector |
| CPU | up to two EV68CB (assumed from the product line; the row allows 2) |
| Chipset | 21274 Titan, four hoses (the console probes all four: "Hose 0 - PCI bus running at 33Mhz", hoses 1-3 at 66 MHz) |
| Memory | assumed up to 16 GB (row: memory.bits 26-34) |
| PCI | not established: every slot is refused until the console's table is read |
| Board hardware | an RMC and a TIG like the ES45's (FWREADME: RMC V1.3, TIG V2.6, SROM V1.4-G, FSB V7.3-3); the row builds the ES40's DPR and a two-part flash **[assumed]** |

## Firmware

`roms/alpha-firmware-v7.3/DS25/DS25_V7_3.EXE`, the update utility, raw
(`FW_RAW_IMAGE`), the same form as the ES45's. Its console reports "OpenVMS
PALcode V1.98-43" and runs up to 0x668000 in memory (`console_bytes`
0x680000).

## Findings

**First run (lab/platforms/es45, `run.sh ds25lfu ... ds25 DS25_V7_3.EXE`):**
the console starts, sizes memory, probes the four hoses, starts its
drivers and enters its idle loop, gives the same "RMC command 9" failure
as the ES45 did before its DPR answered it, initialises dqa/dqb, and then
takes an **access violation** in its powerup process: a longword read at
0x805.0000.0000 (PC 0x1f8274, the console's I/O read helper).

Just before, it wrote the expansion-ROM BAR (0x30) and the command register
of **hose 2 device 1** (configuration 805.FE00.0800), and sent AMD flash
command bytes (0xaa to 0x553, 0x55 to 0x2a8, 0x90 to 0x553: byte-mode
autoselect) into hose 2 memory at 804.0000.0000. Nothing answers at hose 2
device 1, so the BAR read back as all ones; the faulting address is hose 2
memory + 0x1.0000.0000, i.e. a base computed from that. **Interpretation
[guess]:** the DS25 has an on-board PCI device at hose 2 device 1 whose
option ROM is a flash part (the utility's strings name an AIC-7899 SEEPROM,
a Broadcom controller SEEPROM and KGPSA/KZPSA flashes), and the utility
assumes it is there. Which device it is has to come from the console's
device table or a DS25 manual; none is in `lab/docs-titan/`.

Other unclaimed accesses: TIG offset 0x0c0 (psir, the power-supply
register in the ES40's TIG naming) read 7 times.
