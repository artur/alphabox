# AlphaServer ES45 work packet

The first machine on the Titan chipset ([titan.md](titan.md)), and the
second, after the DS20L, brought up by running its own firmware update
utility.

**Branch**: `platform/titan-es45` · **Config**: `platform = "es45";`
· **Status**: L5 (OpenVMS 8.4 boots an installed disk to login on 1, 2 and
4 processors; NIC interrupts checked on all four hoses); L3 structural
against a real ES45's listing

## The machine

| | |
| --- | --- |
| Family, code name | Titan; Linux calls the ES45 "Privateer" (sys_titan.c) |
| CPU | up to four EV68CB (known: owner's guide); the EV68CB row is used, the console names it "Alpha EV68CB pass 4.0 833 MHz 8MB Bcache" |
| Chipset | 21274 Titan: Cchip, Dchips, two PA-chips = four hoses (known: Linux core_titan.h, service guide 1.11) |
| Memory | up to 32 GB in four MMBs (known: service guide); modelled with the Tsunami's DIMM model, 64 MB to 32 GB |
| PCI | hose 0 at 33 MHz, hoses 1-3 at 66 MHz (known: service guide, show config). Model 2(B) slots: hose 0 devices 8-11, hoses 1 and 3 devices 1-2, hose 2 devices 1-2; the Model 1B uses hose 2 device 5 (known: owner's guide tables 1-2..1-4). Hot-plug controllers ("Yukon") at hose 0 device 12 and hoses 1, 3 device 6 (known: listing; not modelled) |
| South bridge | Acer Labs M1543C at hose 0 device 7, its IDE at device **16** (not the ES40's 15) (known: listing, and the console's own configuration write to device 16); no USB is listed |
| Console devices | COM1/COM2, keyboard/mouse, floppy behind the ALi (service guide) |
| Board hardware | RMC (PIC 17C44) behind a dual-port RAM on the TIG bus, as on the ES40; the flash is **two** 2 MB AM29F016 parts on the TIG bus (the update utility programs the second at TIG offset 0x200000) |

## Firmware

`roms/alpha-firmware-v7.3/ES45/ES45_V7_3.EXE` (firmware CD V7.3) is the
update utility, a raw image (`FW_RAW_IMAGE`). It installs SRM V7.3-2 and
SROM V2.22-G:

```
PLATFORM es45, ROM=ES45_V7_3.EXE, answer: <return>, "update", "Y"
SRM             Updating to V7.3-2...  Verifying V7.3-2...  PASSED.
srom            Updating to V2.22-G...  Verifying V2.22-G...  PASSED.
```

(`lab/platforms/es45/lfu-update-console.log`; the flash it leaves is
`lab/platforms/es45/flash-v73.rom`, 4 MB.) The utility runs up to 0x648000
in memory, so the row's `console_bytes` is 0x680000.

The installed SRM partition is at flash offset **0x20000**, behind the same
0x40-byte CPQ header as the ES40's (which is at 0x10000): "CPQ" at +0x14,
"PRIVATEEALPH" at +0x18, the payload size at +0x2c (0xcd800), the name
"SRM" at +0x30, 0x11223344 at +0x3c, then the console's self-decompressor.
Alphabox now searches the flash for such a partition
(`CFlash::FindCpqPartition`) after the ES40's fixed place.

Boot afterwards with the flash and no `rom.srm`:

```
AlphaServer ES45 Console V7.3-2, built on Feb 27 2007 at 13:09:18
P00>>>
```

## Findings

**The ES40's console speed patches hung the ES45 console.** Applied to the
ES45 image (the M0 risk), they replaced words in its scheduler: the console
sat in its idle loop after "create dead_eater" with interrupts off. The
ES45 row has no patch table; the console then runs straight to its prompt.

**The flash is two parts.** The update utility's AMD command sequences go
to 0x5555/0x2aaa of each 2 MB part, and the SRM and SROM images it writes
lie in both (0x20000-0xeffff; 0x2a0000-0x2fffff). `CFlash` takes a part
count (the ES40's one part and its 2 MB file are unchanged).

**The core logic revisions** come from MISC<39:32>, DREV, the G-port SCTL<7:0>
of each PA-chip and the TIG register at offset 0 (printed as
"(<7:4>+2).<3:0>"), found in the console's show-config code (0x96fc0).

**The model** ("Model 1/2/3", "AlphaStation ES45") is chosen in
`build_dsrdb` (0x90e00): the hose 2 A-port's APCTL<57> (AGP present), the
CPU speed (above or below 1001 MHz), and byte 6 of the PCI backplane FRU
EEPROM image the RMC keeps at DPR 0x2900 (1 = Model 3, 2 = Model 2, read
through the console's `dpr` file). Without it the console said "Error
determining system type, Defaulting to AlphaServer ES45 Model 2". The
"B" of the listing's "Model 2B" is not in that code's table; where it comes
from is not known **[open]**.

**RMC command 9** carries one byte computed from an environment variable's
value (is its first character 'F'). The ES40's RMC model answered "invalid
command" and the console printed "RMC command failure". The ES45's DPR now
accepts it; what the real RMC does with it is unknown, so this is a
**value chosen to get past the error**.

**The interrupt map is the console's table** (one word per slot, a byte
per pin, at 0x175220 in its memory) and matches the lines it writes into
cards' configuration space:

| hose | slot: INTA (DRIR bit) |
| --- | --- |
| 0 | 8: 0x14, 9: 0x18, 10: 0x0c, 11: 0x10, 12: 0x0b (one pin) |
| 1 | 1: 0x1c, 2: 0x20, 6: 0x0a (one pin) |
| 2 | 1: 0x00, 2: 0x04, 5: 0x2c (two pins) |
| 3 | 1: 0x24, 2: 0x28, 6: 0x09 (one pin) |

INTB-D are the following bits. The ISA bridge is DRIR bit 55, as on the
ES40 and in Linux; the IDE is routed through ISA (line 0xee). OpenVMS
received ~128 broadcast frames in 40 s on each of five DE500s at hose 0
slot 9, hose 1 slot 2, hose 2 slots 1 and 5 and hose 3 slot 1
(`lab/platforms/es45/nic_check.sh`, evidence/l5-nic-nic1-console.log).

**The ISA devices needed no move:** Titan's hose 0 legacy I/O is at
801.FC00.0000 like the Tsunami's (Linux TITAN_IO(0)), so the hard-coded
addresses in `devices/isa` and the ALi stay right on the ES45.

**OpenVMS 8.4** boots the CD to its install menu, and the disk installed on
the ES40 (`lab/vms84/disk-installed.img`, cloned) to the SYSTEM login on 1,
2 and 4 processors: `HW_NAME` "AlphaServer ES45 Model 2", SYSTYPE 38
(Titan, as the service guide's error log lists it), `SHOW CPU` active 0-3.
The secondaries are started by the console (`SECONDARIES_BY_CONSOLE`, as on
the ES40). Transcripts in `lab/platforms/es45/evidence/`.

**The interpreter runs the console's real PALcode** (`vmspal_pal_base` 0):
the native routines were written for the ES40 console's PALcode.
